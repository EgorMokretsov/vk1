# WukongBench

Инструмент на **C# / .NET 8 для Windows**, который запускает установленный в Steam **Black Myth: Wukong Benchmark Tool** (AppID `3132990`), выполняет CPU- и GPU-проходы, распознаёт FPS с итоговых экранов и создаёт локальные HTML/JSON-отчёты.

**Ссылка для сдачи:** https://github.com/EgorMokretsov/vk1 — публичный репозиторий, доступ без приглашений.

Полный успешный запуск, включая отчёты, скриншоты, OCR, настройки и резервную копию: [results/20261008-231625-133](results/20261008-231625-133). Для просмотра HTML скачайте репозиторий и откройте report.html из этой папки; GitHub показывает исходный HTML. Текст для поля ответа: [SUBMISSION.md](SUBMISSION.md).

**Статус проверки:** полный автоматический сценарий подтверждён на реальной игре 08.10.2026 командой `run.cmd --gpu-resolution 1280x720 --no-ray-tracing --open-report`. Сессия `20261008-231625-133` завершилась со статусом `completed`: CPU 20 / 3 / 26 FPS, GPU 1 / 0 / 2 FPS (средний / минимум / максимум). У обоих проходов `SettingsValidation=verified`; сохранены `effective.ini`, итоговые скриншоты и HTML/JSON. Значения каждого прохода подтверждены двумя снимками. Исходные настройки восстановлены: присутствует `backup/restored.txt`, SHA-256 всех 26 восстановленных INI совпали с резервной копией. Проверенный GPU-профиль — 1280×720, 100%, Cinematic без RT на AMD Radeon(TM) Graphics. Сборка и 138 автоматических проверок проходят. Режим 1920×1080 ранее завершался с GPUCrash и не считается подтверждённым успешным режимом на этом ПК. Уменьшенное GPU-разрешение максимизирует качество в рамках выбранного режима; низкое разрешение CPU-профиля не гарантирует ограничения только процессором.

## Быстрый запуск

1. Windows 10/11 x64; установить **.NET 8 SDK** (включает нужную среду .NET Desktop): [официальная загрузка Microsoft](https://dotnet.microsoft.com/download/dotnet/8.0).
2. В Steam установить бесплатный [Black Myth: Wukong Benchmark Tool](https://store.steampowered.com/app/3132990/). Войти в Steam. **Однократная подготовка установки:** открыть бенчмарк, самостоятельно пройти первый экран соглашения, выбрать English, дождаться окончания первоначальной подготовки и закрыть. Инструмент не принимает соглашения за пользователя.
3. В Windows установить английский OCR: Параметры → Время и язык → Язык и регион → English (United States) → Параметры языка → «Оптическое распознавание символов». Если компонент уже установлен, дополнительных действий нет.
4. Скачать ZIP через GitHub **Code → Download ZIP**, распаковать. Открыть PowerShell в папке проекта и выполнить:

```powershell
.\run.cmd --open-report
```

На проверенном ПК с AMD Radeon(TM) Graphics оба прохода завершились следующей командой (GPU: 1280×720, 100%, Cinematic без RT):

```powershell
.\run.cmd --gpu-resolution 1280x720 --no-ray-tracing --open-report
```

После запуска участия пользователя не требуется: инструмент сам применяет профили, запускает сцену, ждёт результатов и выполняет второй проход. На время работы оставить рабочий стол разблокированным и не использовать мышь/клавиатуру, не перекрывать окно. Steam и инструмент запускаются с одинаковыми обычными правами, администратор не нужен. Основной монитор должен вмещать окно 1280×720; для GPU заранее выбрать в Windows максимальное разрешение монитора. Отключить внешние ограничения FPS и генерацию кадров в драйвере, если они включены.

Результат: `results/<дата-время>/report.html` — откроется в браузере; `report.json` для машинной обработки. В подпапках `cpu/` и `gpu/` находятся скриншоты всех стадий, OCR JSON, `requested.ini` и `effective.ini`; в `backup/` — исходные настройки.

Сборка и запуск отдельными командами:

```powershell
dotnet build src/WukongBench/WukongBench.csproj -c Release
dotnet run --project src/WukongBench -c Release -- --open-report
```

## Выбор настроек

| Параметр | CPU-проход | GPU-проход |
|---|---|---|
| Разрешение | 1280×720, окно | Разрешение основного монитора, безрамочный режим |
| Внутренний масштаб | 50% (около 640×360) | 100%, нативный рендер |
| Метод реконструкции | TSR | TSR при 100% |
| Дальность прорисовки | Cinematic | Cinematic |
| Растительность | Cinematic | Cinematic |
| Тени, освещение, отражения, эффекты, текстуры, AA, волосы | Low | Cinematic |
| Full Ray Tracing | Выключено | Very High для распознаваемых RT-видеокарт; иначе выключено |
| Frame Generation | Выключено | Выключено |
| VSync, ограничение FPS | Выключены | Выключены |
| Динамическое разрешение | Выключено | Выключено |

**CPU:** низкие разрешение и масштаб уменьшают количество обрабатываемых GPU пикселей, Low снижает стоимость эффектов и потребление VRAM. Высокие дальность и растительность сохраняют больше объектов, работу подготовки кадра и отправки команд со стороны CPU. Это практический профиль для уменьшения влияния GPU, а не гарантия полной изоляции: на слабой видеокарте даже он может оставаться ограниченным GPU, а сцена бенчмарка не содержит полноценного игрового боя. Для доказательства конкретного bottleneck потребуются дополнительные измерения времени CPU/GPU или сравнение нескольких разрешений; они не выдаются здесь за результаты самого Benchmark Tool.

**GPU:** нативный рендер и Cinematic увеличивают стоимость пикселей, теней, эффектов, растительности и освещения. Максимальная Full RT дополнительно нагружает поддерживаемую видеокарту. Автоматическое предположение о поддержке делается по названиям RTX / RX 6xxx, 7xxx, 9xxx / Arc, а фактическое включение проверяется в меню; одно название устройства не считается доказательством поддержки. При несовпадении программа останавливается с диагностикой. Для аппаратной/драйверной конфигурации без доступной Full RT используется `--no-ray-tracing`. Такой проход явно помечается как GPU Cinematic без RT. Нагрузка максимизируется **в пределах выбранного разрешения и поддерживаемых функций**, не за счёт неподдерживаемых режимов дисплея.

Генерация кадров отключена, чтобы итоговые FPS отражали реально отрендеренные кадры. VSync и лимит FPS отключены, чтобы частота монитора не ограничивала измерение. TSR выбран как общий метод для разных производителей GPU.

## Как работает автоматизация

- Путь к Steam берётся из реестра; библиотеки — из `libraryfolders.vdf`; установка и build ID — из `appmanifest_3132990.acf`.
- Настройки применяются при закрытом процессе через `b1/Saved/Config/Windows/GameUserSettings.ini`. Обновляются и `ScalabilityGroups`, и сериализованная карта `UISettingData` из секции `GSGameUserSettings`: только группы `sg.*` недостаточны, потому что интерфейс игры может восстановить свои значения. Неизвестные поля сохраняются.
- Запуск: `steam.exe -applaunch 3132990 -culture=en -dx12`. Это запускает приложение через Steam; отдельно запускаемый Shipping EXE не используется. `-benchmark` не выдаётся за команду автоматического запуска этой сцены.
- C# захватывает только окно запущенного бенчмарка, Windows OCR находит английские пункты меню, Win32 `SendInput` управляет ими. Заданы таймауты, проверка фокуса и принадлежности процесса установке. Повторный запуск уже открытого инструмента запрещён.
- Оригинальные снимки сохраняются без изменений; для OCR создаются отдельные увеличенные и осветлённые `*-ocr.png`, а координаты переводятся обратно. Значения ищутся справа от распознанной подписи строки, с исключением колонки справки. При повторяющихся заголовках выбирается строка с распознанным значением; если контрол не найден, случайный клик не выполняется.
- Ползунок `Super Resolution` выбирается по названию без дополнительного слова: заголовок `Super Resolution Sampling` и его OCR-опечатки не принимаются за ползунок. Мелкое числовое значение дополнительно читается из увеличенной области справа от подписи, с сохранением контраста и обратным переводом координат. У выделенного ползунка дополнительно появляются крайние подписи 33 и 100; они исключаются из текущего значения. При нечитаемом подвижном поле OCR выполняется строго между распознанными крайними подписями. Само наличие подписи 100 справа не подтверждает масштаб 100%. Диагностика сохраняется в `*-values-ocr.png` и `*-values.json`.
- Для выбора TSR и других значений строка сначала выделяется нажатием на распознанный контрол, затем используются клавиши Left/Right. После каждого шага значение читается заново. При достижении края проверяется другое направление; повторяющиеся значения, лимит попыток и потеря распознавания останавливают перебор. Наличие выпадающего списка не предполагается.
- Колёсико направляется на распознанную строку внутри списка графических настроек, а не на фиксированную координату в области справки. Уже видимые параметры проверяются без лишней прокрутки. Для остальных поиск возвращается к началу списка и выполняет ограниченный перебор; появление/исчезновение строк или изменение их координат подтверждает движение. Если список не изменяется, поиск останавливается с диагностикой.
- В меню проверяются качество каждого графического параметра, FG и RT; TSR и масштаб задаются через видимые контролы, без предположений об их числовой сериализации. После прохода настройки, сохранённые самим приложением, сверяются с профилем.
- На неподдерживаемом оборудовании строка Full RT может быть затемнена без текста `Off`. Для профиля с выключенным RT допускается проверка по конфигурации только при пустом значении и существенно меньшем контрасте подписи относительно активной строки FG. Это визуальная эвристика, а не аппаратный API поддержки RT. Дополнительно обязательно проверяются `UISettingData/Rtx=0` и `r.RayTracing.EnableInGame=False` до запуска сцены и после закрытия приложения. В отчёт сохраняется `rt-disabled.json`; видимое `On`, активная строка без читаемого значения или включённый RT в конфигурации приводят к отказу.
- При распознанном пункте `T: Apply Graphics Changes` внизу меню инструмент явно применяет изменения и проверяет, что признак несохранённых настроек исчез. Выход из меню сам по себе не считается применением.
- Steam запускает приложение асинхронно. Перед GPU-проходом ожидается событие Remove 3132990 from running list в хвосте Steam logs/gameprocess_log.txt (до 60 секунд, с отменой); до подтверждения новый профиль и запрос запуска не применяются. Недоступный журнал означает неизвестное состояние и завершение по таймауту. Статус сохраняется в gpu/steam-release.json. Перед отправкой нового запроса сохраняется список существующих PID; для следующего прохода также исключается PID уже завершённого предыдущего. Исключённый PID пропускается до обращения к MainModule/StartTime, чтобы завершающийся CPU не вызвал ошибку доступа. Временные ошибки чтения нового PID повторяются в пределах общего таймаута; PID, сообщение и код Windows сохраняются в launch-inspection-errors.json. Начальная проверка уже открытого приложения остаётся строгой и сохраняет исходное исключение. Принимать можно только живой процесс с правильным исполняемым файлом и временем создания не раньше нового запроса. Ожидание длится до трёх минут; завершавшийся CPU-процесс не считается GPU-запуском. В каждом каталоге прохода сохраняется launch.json с моментом запроса, исключёнными PID и выбранным новым PID. Дескриптор нового процесса сохраняется, пока процесс работает, чтобы код выхода оставался доступен после его завершения. При фактическом завершении ошибка содержит PID и код выхода; недоступный код не заменяет сообщение об исходном сбое. Если Benchmark Tool создал CrashContext.runtime-xml для того же PID после нового запуска, в crash.json сохраняются только тип сбоя, сообщение, флаг OOM, доступная память, GPU и версия драйвера. Полный контекст с идентификаторами учётных записей не копируется.
- Перед запуском включается штатный пункт `Display Frame Rate Information`. Для подтверждения работающей сцены требуется подпись `Current FPS` в левом верхнем углу, читаемое число под ней и `Exit` справа внизу. Для маленькой подписи допускаются до двух OCR-ошибок символов и объединённые слова (например, `CurratFPS`), числовые значения не исправляются предположениями. Меню, подтверждения и старые результаты не принимаются за запуск; загрузка ожидается до трёх минут в пределах общего таймаута. На основном участке ожидания OCR не работает; после 145 секунд проверяется появление итогового экрана, а не просто окончание фиксированной паузы. Текущий FPS используется только как признак работающей сцены, а не как результат прохода.
- Источник чисел — **итоговый экран Benchmark Tool**: средний, минимальный и максимальный FPS. Распознавание связывает цифры и подписи по координатам, проверяет диапазон и `min ≤ avg ≤ max`, затем требует одинаковые значения на двух снимках. Итоговая таблица настроек не обрабатывается как интерактивное меню. При плохом полном OCR отдельно увеличивается колонка результатов, определённая по её заголовку и соседнему заголовку Operating System. Если цифра читается как буква, области чисел под точными подписями собираются в отдельное OCR-изображение без FPS; читаются реальные пиксели и координаты возвращаются к исходным подписям. Если OCR полностью пропустил крупное среднее число, его область находится по ярким компонентам изображения под точной подписью Average, с исключением маленького FPS. Область читается повторно через OCR; пиксели не используются для угадывания значения. Числовые фрагменты проверяются с двумя вариантами расстояния между ними, чтобы OCR не склеивал соседние показатели. Буква I не заменяется на 1, непрочитанные/неоднозначные цифры остаются ошибкой. На итоговой таблице выводится прогресс чтения; после трёх неудачных снимков программа останавливается с ошибкой и восстановлением настроек, вместо многоминутного повторения. Промежуточные изображения и OCR JSON сохраняются для проверки. Внешний счётчик FPS и `LastCPUBenchmarkResult` Unreal Engine не используются как результат Wukong.
- Если обработка тусклого меню ухудшила чтение цифр на итоговом экране, OCR повторяется без изменения контраста и размера. Альтернативное чтение принимается только при полном наборе корректных FPS; ожидаемые числа не подставляются.
- Исходные INI сохраняются побайтно вместе с атрибутами. В `finally` закрывается только запущенный инструментом процесс и восстанавливается конфигурация. При аварийном завершении процесса программы/питания восстановление доступно отдельной командой.

Архитектура: `WukongBench.Core` — профили, INI, парсер; `WukongBench` — Steam, Windows, UI, отчёт; два небольших PowerShell-адаптера — штатный Windows OCR и CIM для CPU/GPU/RAM/ОС/драйверов/платы. Внешних NuGet-библиотек, OCR-сервисов и API-ключей нет. Данные остаются локально.

## Дополнительные команды

```powershell
# Характеристики и проверка наличия Steam-установки
.\run.cmd --doctor

# GPU без full RT
.\run.cmd --no-ray-tracing --open-report

# Нестандартные пути
.\run.cmd --game-dir "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool" --config "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool\b1\Saved\Config\Windows\GameUserSettings.ini"

# Разрешение, которое помещается на основном мониторе; таймаут прохода в секундах
.\run.cmd --gpu-resolution 2560x1440 --timeout 1200

# После GPUCrash в 1080p Cinematic: диагностический проход при меньшем разрешении
.\run.cmd --gpu-resolution 1280x720 --no-ray-tracing --open-report

# После аварии: сначала закрыть бенчмарк, затем восстановить резервную копию
.\run.cmd --restore "results\20261006-120000-000\backup"

# Независимо проверить OCR и парсер на своём снимке итогового экрана
.\run.cmd --parse-image "C:\BenchResults\results.png"
```

Если программа остановилась, открыть `error.txt`, `report.html` и последние скриншоты в каталоге результата. При изменённом интерфейсе или неанглийском тексте она выдаст ошибку, вместо успешного отчёта с неподтверждёнными настройками. Если GPU Full RT недоступна — повторить с `--no-ray-tracing`; если пути отличаются — использовать `--config`. Время OCR-проверок меню не входит в FPS-метрики бенчмарка. Явный GPU-размер меньше основного экрана использует проверенный оконный режим; 100% масштаба и Cinematic сохраняются. Это диагностический профиль с меньшей нагрузкой по числу пикселей, а не заявление о максимально возможной нагрузке в 1080p. Он не гарантирует устранения GPUCrash; автоматическое снижение качества или разрешения не выполняется.

## Проверка решения

```powershell
dotnet run --project tests/WukongBench.Tests -c Release
```

Пройдено **138 автоматических проверок**: границы INI-секций и сохранение неизвестных полей, оба профиля, отказ при переопределении настроек, цифры на строке и над подписями FPS, десятичная запятая, отказ от текущего FPS и противоречивых результатов, побайтное восстановление конфигурации/атрибутов, защита путей резервной копии и формирование отчёта. Проверки меню включают фактические OCR-координаты установленного приложения, отдельные и объединённые строки значений, повторяющийся и ошибочно распознанный заголовок, исключение справки, числовую область ползунка, изменение размера окна и признак неприменённых настроек. По реальному GPU-снимку проверяются исключение крайних подписей ползунка 33/100, отказ при отсутствии подвижного значения, область OCR между границами, подвижные значения 100/50/33 и другой размер окна. Проверяются признаки затемнённого RT и отказ при включённом RT в конфигурации. Детектор запуска проверяется на фактических OCR-данных сцены с опечаткой CurratFPS, отсутствующим суффиксом FPS и загрузкой без читаемого числа; отдельно проверяются положение Exit, близость числа к подписи, другой размер окна и отказ при меню, старых результатах или нечитаемых значениях. Прокрутка проверяется по фактическим неподвижным снимкам: точка внутри списка, исключение справки, распознавание движения, поиск скрытого параметра на имитируемом следующем экране и остановка при отсутствии движения. Переключение стрелками проверяется на сохранённых OCR-данных выделенной строки с имитацией ответов интерфейса: выбор TSR, смена направления на краю, уже выбранное значение и остановка при потере распознавания или отсутствии изменений. Выбор процесса при повторном Steam-запуске проверяется на ситуации из журнала: CPU PID 20816 ещё перечисляется, а новый GPU PID 10836 появляется через восемь секунд; также проверяются завершённый новый процесс, время создания до запроса, стабильность снимка исключённых PID и недопустимый PID. Дополнительно тест воспроизводит последний сбой PID 13348 через недоступный getter MainModule/StartTime: getter не вызывается для исключённого процесса. Проверяются повторное чтение нового PID после ошибки Windows, сохранение её кода, отказ при другом exe или времени до запроса, строгая начальная проверка. По событиям журнала Steam проверяются ожидание завершения предыдущей сессии, игнорирование других приложений и отдельных дочерних PID, ограничение ожидания при неизвестном состоянии, отмена и чтение хвоста большого файла. Также проверяются чтение кода выхода отдельного служебного процесса через объект, найденный по PID, безопасное сообщение при недоступном ExitCode, различение GPUCrash и OOM, исключение другого PID и старого файла сбоя, сохранение только выбранных полей, а также оконный режим уменьшенного GPU-профиля с сохранением 100%/Cinematic. Дополнительно проверяются фактический GPU-результат 1/0/3 с нулевым минимумом, положительный дробный средний FPS, отказ при нулевом среднем, точное чтение цифрового слова в отдельной области и отказ при I/O, лишних числах и числе вне исходной области. Эти тесты не запускают Steam и не проверяют ввод клавиш или колёсика в работающей игре.

Распознавание итогового экрана также проверяется по реальным OCR-данным: отделение таблицы настроек от меню, область колонки FPS, отказ при букве вместо цифры, связь числовых фрагментов с исходными подписями, пропущенные значения и неоднозначные подписи. По реальному фрагменту среднего числа 20 проверяются поиск крупных цифр без OCR-координат, исключение FPS, отказ на пустом изображении и лишнем ярком объекте. Полный Windows OCR на сохранённом снимке CPU проверяется отдельной командой (добавляет одну интеграционную проверку):

```powershell
dotnet run --project tests/WukongBench.Tests -c Release -- --result-evidence "C:\path\to\cpu-results.png"
```

Этот режим не запускает игру. Без третьего аргумента он проверяет сохранённый контрольный снимок с FPS 19 / 1 / 25. Для снимка со средним / минимальным / максимальным FPS 20 / 2 / 26:

```powershell
dotnet run --project tests/WukongBench.Tests -c Release -- --result-evidence "C:\path\to\cpu-results-20.png" "20,2,26"
```

Сохранённые CPU-снимки проверены полным Windows OCR-парсером локально. Дополнительно два GPU-снимка с FPS 1 / 0 / 3 и CPU-снимок 20 / 3 / 26 прошли тот же полный путь. Для проверки очень медленного GPU используется третий аргумент "1,0,3". Минимум 0 допускается, если средний FPS положителен и минимум ≤ средний ≤ максимум. После неудачи общей полосы цифр каждый показатель читается отдельно с настоящим суффиксом FPS из таблицы. Если OCR пропускает одиночную цифру, её исходные пиксели увеличиваются и инвертируются, а рядом добавляются только буквы FPS в сопоставимом размере; цифровые значения не вставляются. Числовое слово обязано находиться внутри области исходной цифры, лишние/буквенные/противоречивые чтения отвергаются. В results-crops.json, results-avg/min/max-native и results-avg/min/max-context-* сохраняются координаты, картинки и ответы OCR. Совпадение метрик по двум независимым снимкам остаётся обязательным.

Дополнительно локально выполнены две проверки на сохранённом реальном GPU-снимке с выделенным ползунком и крайними подписями 33/100: Windows OCR прочитал масштаб `100`, анализ контраста подтвердил затемнённую строку RT. Для повторения на соответствующем снимке (масштаб 100, недоступный RT):

```powershell
dotnet run --project tests/WukongBench.Tests -c Release -- --menu-evidence "C:\BenchResults\graphics.png"
```

Также повторно проверено чтение синтетического PNG с FPS 60.5 / 40 / 90 (это проверка OCR, **не замер игрового FPS**). GitHub Actions собирает приложение, запускает 138 проверок и публикует архив сборки; для него нужен установленный .NET 8 Desktop Runtime на ПК запуска.

Практическая проверка выполнена на реальной установке: сессия `20261008-231625-133` содержит два прохода, статус `completed`, обе проверки настроек `verified` и маркер восстановления. HTML/JSON сверены с итоговыми скриншотами CPU 20/3/26 и GPU 1/0/2; все 26 INI восстановлены побайтно. Первый неудачный OCR-снимок GPU вызвал предусмотренную повторную попытку; следующий был прочитан и затем подтверждён отдельным снимком. При проверке на другом ПК следует также сравнить числа отчёта с обоими итоговыми скриншотами, проверить фактические параметры в `effective.ini` и `backup/restored.txt`.
